In dictionary learning, every data point is written as a sparse combination of atoms. The question this primer answers: when we add tensor decomposition to the mix, what exactly gets decomposed?

Short answer — the atoms. Not the sparse codes. Let's see why, and what that buys us.

§ 01 / FOUNDATION

First, the classic picture: data = dictionary × sparse code.

Before we talk about tensors, let's make sure the basic factorization is clear. In ordinary dictionary learning, you start with a pile of data — say, a thousand image patches, each flattened into a vector.

You then ask: can I find a small set of atoms (call them d₁, d₂, …, d_K) such that every data point in my pile can be written as a sparse combination of these atoms?

"Sparse" means only a handful of atoms are active for any given data point — most coefficients are zero.

So we end up with three objects: the data matrix Y, the dictionary D (the atoms, stacked as columns), and the sparse code matrix X (the coefficients).

Figure 01
The matrix factorization Y ≈ D · X

Each column of Y is a data point. Each column of D is one atom. Each column of X tells us which atoms (and how much of each) build that data point. The dots in X are non-zeros — most cells are blank.

§ 02 / THE PROBLEM

But real data isn't a flat vector — it has shape.

A hyperspectral image is height × width × wavelength. An fMRI scan is x × y × z × time. To use classic dictionary learning, we have to flatten all that structure into a single long vector. Each atom then has to relearn the structure from scratch — wasteful, and noisy.

Figure 02
A hyperspectral pixel cube becomes a flat vector — structure lost

Flattening turns a richly structured tensor into a vector of numbers with no built-in knowledge that some indices are spatial and others spectral. The dictionary then has to learn this from data — expensive in samples, and easy to overfit noise.

§ 03 / THE INSIGHT

The fix: keep Y = D · X, but give each atom in D tensor structure.

Here is the answer to your question: tensor decomposition is applied to the atoms — not to the sparse code matrix X.

The sparse codes stay scalars (just numbers saying "use this much of atom k"). What changes is that each atom D_k is no longer a generic vector — it is a structured low-rank tensor, written as a small set of mode-specific factor vectors.

So the dictionary is now a dictionary of tensor atoms, and each one is parameterized by far fewer numbers than its flat-vector cousin.

Concretely, for a hyperspectral atom of size H × W × C:

  • A generic atom needs H·W·C parameters.
  • A rank-1 tensor atom needs only H + W + C parameters — a spatial-vertical factor, a spatial-horizontal factor, and a spectral factor — multiplied together (an outer product).

That's the whole trick. Below is the picture.

§ 05 / FAMILIES

Three flavors of tensor atom: CP, Tucker, TT.

"Tensor decomposition" isn't one thing — it's a family. Each choice trades parameter count against expressivity in a different way. Same dictionary-learning skeleton, three different atom parameterizations.

CP / CANDECOMP-PARAFAC

Sum of rank-1 outer products

The simplest. Each atom is a sum of R rank-1 tensors — like the picture above, but R of them added together. Most parsimonious; can be too restrictive for complex patterns.

params: R · (H + W + C)
TUCKER

Core tensor + factor matrices

A small "core" tensor multiplied along each mode by a factor matrix. Far more expressive than CP — captures interactions between modes — but the core itself can be parameter-heavy.

params: r·H + r·W + r·C + r³
TT / TENSOR-TRAIN

A chain of small tensors

Each atom is a chain of small 3-way tensors, each linking to the next by a shared "bond" index. Scales gracefully to many modes; popular for high-order data.

params: ~ r²·(H + W + C)

The original passage you shared concerns exactly this choice: under a fixed parameter budget, which family produces the best dictionary? The literature has rarely compared them head-to-head with parameters held equal — that is the gap your work fills.

§ 06 / RECAP

So, where does the tensor decomposition live?

In the dictionary. The atoms are tensor-structured. The sparse code remains a flat vector of scalars — one coefficient per atom, mostly zero.

You can think of it as a clean division of labor:

The sparse code says which atoms are active and how much of each. It carries the locally-adaptive part of the model.

The tensor atoms say what those atoms look like. Their structure encodes the prior knowledge that data has multiple modes that interact in low-rank ways.

This split gives you the three advantages from the original passage at once: parameter efficiency (atoms are tiny), implicit regularization (atoms can't represent unstructured noise), and interpretability (each mode factor has a physical meaning).
